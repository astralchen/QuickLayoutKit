# 聊天模块自适应 UI 设计规格

日期：2026-11-04。设计方向：用户选定的方案 3「沉浸对话」。适用范围：iPhone、iPhone Duo、iPad 的会话列表、聊天详情、搜索、键盘和草稿状态。

本规格是设计交付稿，不代表功能已经实现或验收。用户已选择视觉方向，并要求保持不改代码；下述尺寸、切换阈值和新增交互是本轮设计建议。后续实现以实际容器几何、大字体及系统导航行为验证这些建议。

## 设计目标与范围

窄容器逐页浏览列表和详情，宽容器并排呈现两者。窗口尺寸变化时延续当前会话、阅读位置与草稿；键盘占用高度不单独改变分栏模式。输入区始终属于当前会话，附件与长文本不会无限挤占消息区。

沿用白色基础面、紫色导航与选中强调、蓝色发送气泡、浅灰接收气泡。全局目的地保持「示例／聊天／语音房」。不新增通话、联系人管理、消息全文搜索或跨窗口会话同步；新会话按钮的联系人选择流程待单独设计。

## 容器尺寸与布局建议

所有尺寸单位为 pt，表示逻辑布局尺寸。可用宽度 W 指消息模块扣除外部安全区、系统保留区域与外部导航占位后的实际宽度，尚未扣除内部会话列表。不可直接用设备屏幕宽度、设备名称或横竖屏作为分栏条件。

| 参数 | 普通字体下的起始建议 | 约束 |
| --- | --- | --- |
| 进入双栏 | W ≥ 760 | 同时满足两栏最小内容宽度 |
| 从双栏收为单栏 | W < 720，或两栏内容无法保持可读 | 720–759 保持原有模式，避免临界宽度反复切换 |
| 首次进入模块 | W ≥ 760 且内容可读时双栏，否则单栏 | 不依赖之前不存在的模式 |
| 会话列表宽度 | 默认 300，范围 280–340 | 紧凑双栏优先收窄列表，不能无限压缩详情 |
| 聊天详情最小宽度 | 建议 420 | 不满足时使用单栏；大字体可提高最小宽度 |
| 消息阅读区最大宽度 | 620 | 宽详情中居中；消息与输入内容使用相同水平基准 |
| 单栏内容边距 | 普通宽度 16，极窄容器可降至 12 | 安全区只消费一次 |
| 分栏分隔线 | 1 个物理像素 | 不用厚边框或卡片阴影分隔两栏 |

例如 W=720 时可分配列表 280、细分隔线及约 439 的详情空间。若大字体使任一栏不再可读，即使达到普通字体阈值也应转为单栏。阈值是待验证的产品布局建议，不是 UIKit 固定规则。

高度变化单独控制聊天区与输入区预算：停靠键盘、横屏低高度或窗口缩短都不直接触发分栏。系统保留区域若同时减少可用宽度，则按新的 W 重新判断。

## 导航与状态切换

| 当前状态与动作 | 目标界面 | 保留内容与焦点 |
| --- | --- | --- |
| 窄容器列表点击会话 | 单栏聊天详情，顶部返回「聊天」，隐藏全局 Tab | 保存列表滚动位置；进入时不自动弹出聊天键盘 |
| 单栏详情点击返回 | 原列表或原搜索结果 | 保存该会话草稿和消息阅读位置；聊天输入退出焦点 |
| 宽容器首次进入且未选会话 | 列表＋「选择一个会话」占位 | 无输入栏，不自动选择第一项 |
| 宽容器点击列表会话 | 更新右侧详情与选中背景 | 保存旧会话草稿；恢复新会话状态，不自动聚焦输入 |
| 详情打开时由宽变窄 | 继续显示当前详情 | 保留消息锚点、草稿、选区与有效输入焦点 |
| 未选会话时由宽变窄 | 显示会话列表 | 不产生空详情页 |
| 单栏详情由窄变宽 | 列表＋当前详情 | 恢复列表中的对应选中项 |
| 单栏列表由窄变宽 | 有最近会话则恢复对应详情，否则显示占位 | 保留搜索条件与列表位置；不自动弹键盘 |
| 宽容器点击收起列表 | 当前聊天扩展至可用区域 | 保留恢复列表入口；不改变当前会话 |
| 临时收窄再恢复宽度 | 恢复用户上次显式展开或收起列表的偏好 | 系统强制折叠不覆盖用户偏好；偏好作用于当前场景会话 |
| 切换其他全局 Tab 再返回 | 恢复当前消息页面 | 保存会话与草稿；离开时收起键盘，返回不自动抢焦点 |

宽容器收起列表后，恢复列表入口必须仍可见。未选中会话时不提供没有意义的「专注聊天」状态。顶部搜索入口如果随系统工具栏出现，与列表搜索框指向同一个搜索状态，不能形成两套搜索。

## 组件尺寸与视觉建议

以下为普通字体的起始参数。大字体允许组件增高与重排，不能通过缩小正文来强行满足这些尺寸。

| 组件 | 建议 | 内容规则 |
| --- | --- | --- |
| 会话标题 | 17，Semibold | 一行；过长截断，辅助功能读完整名称 |
| 会话预览 | 15，Secondary | 普通字体一行；草稿前缀单独强调 |
| 会话时间 | 12–13，Secondary | 固定在行尾，不挤压到名称上 |
| 列表行 | 默认最小高度 76 | 大字体自然增高；整行可点 |
| 头像 | 列表 48；消息旁 28–32 | 头像不承担唯一的姓名识别信息 |
| 未读角标 | 最小 18，随数字增宽 | 只表达未读，选中背景单独表达当前会话 |
| 搜索框 | 默认高度 40–44 | 清空与取消分别可触达 |
| 消息正文 | 默认 17 | 支持换行及动态字体 |
| 气泡 | 内边距水平 12、垂直 8–10；圆角约 18 | 最大宽度为阅读区约 78%，长词与链接可换行 |
| 消息间距 | 同组约 4–6，不同组约 12 | 不依赖每条消息都显示头像或时间 |
| 输入框 | 单行最小约 44，正文 17 | 多行向上增长；不遮挡发送按钮 |
| 图标按钮 | 点击范围至少 44×44 | 图形可小于点击范围；不重叠其他目标 |
| 附件缩略图 | 约 72×72，圆角约 12 | 横向排列，移除按钮独立命中 |

浅色强调色沿用项目资源中的 #7655D6，深色强调色参考 #A78BFA；正文、背景、分隔线优先使用语义颜色。发送气泡沿用系统蓝，接收气泡使用浅灰语义填充。小字不单靠降低透明度处理；深色与增强对比度状态需另行视觉检查。

## 会话列表与空状态

列表显示头像、名称、最后活动时间、最近消息或草稿摘要、未读数量。草稿存在时摘要优先显示「[草稿]」与文字；只有照片时显示「[草稿] 2 张照片」。草稿不是已发送消息，不更新为发送成功时间。已存在的置顶规则可保持，普通会话按最后消息时间排序；本规格不引入因每次编辑草稿而跳动的排序。

双栏用淡紫色标识当前会话，单栏列表不显示详情选中背景。未读状态由实际阅读行为更新，不能仅因条目被选中就假定全部已读。设计图的林小夏是已读示例，陈一诺有 2 条未读。

| 状态 | 文案与入口 |
| --- | --- |
| 有会话但未选中 | 右侧「选择一个会话／从左侧选择，继续聊天」；无输入栏 |
| 完全没有会话 | 列表区域「还没有会话」，保留新建会话入口；不显示虚构联系人 |
| 搜索无结果 | 「没有找到相关会话／试试其他名字」；保留查询、清空和取消 |
| 当前会话暂无消息 | 详情显示联系人和输入栏，可显示「开始聊天」轻提示；不显示假的历史消息 |

## 搜索与焦点

本轮搜索范围为会话名称，不包含消息正文、附件内容或联系人全局目录。名称匹配范围内突出命中文字，结果保留草稿或最近消息摘要。多语言匹配策略与拼音支持不在本轮定案。

| 动作 | 列表状态 | 详情与键盘 |
| --- | --- | --- |
| 激活搜索 | 显示取消入口，保留已有查询 | 搜索框获得焦点；窄容器隐藏底部全局 Tab |
| 清空查询 | 展示未筛选列表，搜索仍激活 | 保留搜索焦点与键盘 |
| 取消搜索 | 退出搜索并恢复进入前的列表位置 | 收起搜索键盘，不自动将焦点交给聊天输入 |
| 点击结果 | 保存查询及结果滚动位置 | 窄容器进入详情；宽容器更新右侧；收起搜索键盘 |
| 从详情返回结果 | 恢复查询与结果位置 | 不自动弹搜索键盘；再次点击搜索框才输入 |
| 宽容器搜索隐藏了当前会话 | 左侧只展示匹配项，允许没有选中行 | 右侧保留已打开的会话，不因过滤而清空草稿或跳转 |

搜索框与聊天输入框同一时刻只有一个获得输入焦点。容器切换时若当前焦点对应区域被隐藏，应结束该区域输入并保存内容，不将焦点隐式转移给另一个输入框。

## 键盘与消息阅读位置

| 键盘状态 | 输入栏 | 列表与消息区域 |
| --- | --- | --- |
| 收起 | 位于详情底部可用区域 | 使用剩余可用高度 |
| 停靠 | 紧贴键盘顶部，只占详情宽度 | 双栏保留，两栏可视高度缩短；键盘范围以实际遮挡为准 |
| 浮动 | 保持详情底部，不创建整条键盘高度的占位 | 仅在实际遮挡输入或焦点内容时局部避让；浮动键盘位置由用户控制 |
| 外接键盘 | 保持底部输入栏 | 不预留软键盘高度，仍考虑系统附件栏实际遮挡 |
| 交互式收起 | 随真实键盘位置连续变化 | 不先跳到底部再回弹；阅读锚点连续 |

图中的浮动键盘位于列表上方，只表示一种未遮挡输入区的摆放方式。不能假定它始终在左侧，也不能要求用户按图放置。

用户正在查看最新消息时，键盘与输入区高度变化后保持最新消息可见。用户正在阅读历史时，保留可见消息身份及其相对位置，不强制跳到最新消息。新消息到来可显示「新消息」入口；用户点击后才转到最新消息。本人发送成功后转到新发送消息。

## 长文本与低高度预算

输入框从单行向上增高，普通高度下建议最多显示约 5 行，更多文字在输入框内滚动。低高度下优先降为约 2–3 行；行数是起点，不是固定上限。换行键用于换行，发送使用独立按钮；输入法组词期间不能误触发发送。

可用高度不足时依次压缩装饰性间距、限制多行编辑高度、紧凑呈现附件，再缩短消息区。保留联系人导航和可操作的发送入口。极端低高度下可暂时只保留少量历史消息，不缩小键盘或将按钮裁出容器。

附件存在且高度紧张时，缩略图区域可收为「2 个附件」一行入口，点击展开预览；不自动移除附件。该紧凑状态作为后续视觉补图项。输入光标必须保持可见，容器改变后恢复文字选区，但不强制保留已被用户主动结束的键盘焦点。

## 附件草稿与发送条件

照片草稿在文字上方横向排列，数量增加时横向滚动，不增加多行缩略图。点击缩略图进入预览，关闭后回到同一草稿；移除附件不清空文字。输入框上方的草稿缩略图与历史中的图片消息是不同内容，不可因选入照片就将其插入时间线。

| 草稿状态 | 附件呈现 | 发送行为 |
| --- | --- | --- |
| 无文字且无附件 | 输入占位 | 不可发送空消息 |
| 有可发送文字且无附件 | 普通文本输入 | 启用发送 |
| 所有附件就绪 | 显示预览与移除入口 | 有无附言均可发送 |
| 任一附件导入中 | 对应位置显示「正在导入」与进度，可移除 | 暂停整份草稿发送；文字仍可编辑 |
| 任一附件导入失败 | 原位置显示「导入失败」、重试与移除 | 解决或移除失败项后才可发送剩余内容 |
| 正在提交草稿 | 防止重复点击提交 | 保留草稿直到提交成功；失败恢复可重试状态 |

「全部附件就绪后才发送」是本轮拟定的产品规则，实施前需要与现有发送流程核对，不能默认当前代码已采用此规则。导入中表示本地媒体准备，不标成上传中。移除一个仍在导入的项目后，晚到结果不应再次出现。

文字草稿、附件顺序、导入状态按会话隔离。切换会话不得把附件带到另一人的输入栏；返回时恢复原草稿。音频预览、文件草稿沿用已有功能边界，不将本轮照片图解释为音频和照片可任意混合发送的承诺。

## 需要延续的界面状态

| 状态 | 归属 | 容器变化 | 离开当前页面 |
| --- | --- | --- | --- |
| 最近选择的会话 | 当前消息模块场景 | 保留身份 | 返回模块恢复 |
| 列表与搜索结果位置 | 各自列表状态 | 保留可见条目锚点 | 返回对应列表恢复 |
| 搜索词与是否正在筛选 | 当前消息模块场景 | 保留查询；焦点按可见区域处理 | 从结果进入详情后仍保留 |
| 消息阅读位置 | 每个会话 | 保留消息锚点；处于底部时跟随底部 | 返回会话恢复 |
| 文字与附件草稿 | 每个会话 | 保留内容和附件顺序 | 返回会话恢复 |
| 光标与文字选区 | 每个会话编辑状态 | 保留有效范围 | 再次编辑时恢复；不自动打开键盘 |
| 用户显式收起列表偏好 | 当前场景会话 | 临时收窄不覆盖偏好 | 当前场景内保留 |

此表约定页面间与容器间的延续，不扩展为进程重启后的所有 UI 状态持久化要求。持久化草稿继续按项目既有生命周期处理。

## 大字体与可访问性

布局在中英文长名称、RTL 和大字体下允许行高增加与双栏收拢。RTL 将 leading/trailing 镜像，返回方向与列表位置随语言变化；不能把文中的「左列表右详情」硬编码为所有语言的物理方向。

VoiceOver 的列表朗读顺序为名称、草稿或消息摘要、时间、未读数；详情按时间线顺序朗读后到输入区。图标提供明确名称，例如「添加附件」「移除第 2 张照片」「发送消息」。当前会话和失败状态需有文字或辅助功能语义，不能只用紫色或红色区分。焦点移动不应随窗口缩放无故重置。

支持键盘访问搜索、返回与发送入口；具体快捷键沿用项目约定。减少动态效果时弱化分栏和键盘联动动画，保持最终布局与内容状态一致。

## 后续验证与未定项

以下是实现阶段的验收清单，本轮没有执行 App 构建或 UI 测试。

- [ ] 在 320、390、600、719、720、759、760、834、1024 pt 等实际可用宽度及连续拖动过程中检查分栏，覆盖最大辅助字体；示例宽度不代表设备型号。
- [ ] iPhone 与 Duo 窄容器从列表进入详情、返回列表，Tab 与导航栏不重复，列表位置延续。
- [ ] Duo 展开与收拢、iPad 窗口连续缩放，分别在未选会话、搜索、编辑、阅读历史时检查状态延续。
- [ ] 停靠、浮动、外接与交互收起键盘不会遮挡输入光标、附件移除或发送按钮；键盘高度变化不导致无必要的分栏切换。
